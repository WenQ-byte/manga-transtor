## 一、项目概述

### 1.1 项目名称
漫画多语言智能翻译系统（Manga Intelligent Translator，简称 MIT）

### 1.2 项目背景
- 全球漫画市场持续增长，但语言壁垒阻碍了优质海外漫画的分发与阅读
- 人工翻译成本高、周期长，中小出版社难以负担
- 现有开源工具（如 manga-image-translator）功能强大但配置复杂、缺乏友好界面，普通用户与出版社难以使用
- 目标：打造**零配置、一键式**的Web翻译平台，让「上传→翻译→下载」三步完成

### 1.3 项目目标
- **核心目标**：上线一套Web应用，实现单张漫画图片的多语言翻译（首发日语→中文、英语→中文），保持原排版
- **差异化目标**：图形化专有名词录入、清晰的分步进度反馈、一键部署，对标竞品补足易用性短板
- **商业目标**：服务漫画爱好者与出版社两类用户，为后续商业化（订阅制/增值功能）奠定基础

### 1.4 项目定位
| 维度 | 定位 |
|------|------|
| 用户 | 漫画爱好者、引进国外漫画的出版社 |
| 价值 | 降低漫画翻译门槛，秒级获得保持排版的翻译结果 |
| 形态 | Web应用（Python FastAPI + Web前端） |

## 二、市场与竞品分析

### 2.1 市场机会
- 漫画读者基数庞大，跨语言阅读需求旺盛，但缺少易用的工具化产品
- 出版社审阅样张、快速评估海外作品存在真实高频场景
- 现有方案要么专业门槛高（开源工具），要么质量不稳（通用翻译器）

### 2.2 竞品概况（manga-image-translator）
- 10.3k Star 开源项目，Python/FastAPI 实现，GPL-3.0
- 技术完整：检测→OCR→翻译→修复→渲染，支持20+翻译引擎
- **短板**：部署复杂（15GB镜像）、30+配置参数门槛高、无用户系统、专有名词需编辑文本文件、UI偏工程风格

### 2.3 差异化优势
| 竞品短板 | 本产品对策 |
|----------|-----------|
| 配置复杂、门槛高 | 三步操作零配置 |
| 无友好Web界面 | 精心设计的中文UI（ui-ux-pro-max 设计规范） |
| 专有名词需编辑文件 | 图形化录入界面 |
| 部署复杂 | Docker Compose 一键启动 |
| 反馈弱 | 分步进度条（检测→识别→翻译→渲染） |

## 三、项目范围

### 3.1 功能范围

**P0（MVP必做，10项）**
1. 图片上传（单张，JPG/PNG/WebP，建议≤10MB）
2. 语言选择（下拉框：日→中、英→中）
3. 文本检测 + OCR识别（漫画专用模型）
4. 机器翻译（保持原排版）
5. 图像修复 + 渲染
6. 分步进度条反馈
7. 结果网页预览
8. 单张图片下载
9. 专有名词管理（自定义词典 + 内置词库）
10. 错误处理（OCR失败提示「图片模糊」等）

**P1（首个迭代，6项）**：批量上传、ZIP打包导出、自动检测源语言、词典导入/导出、竖排文字支持、移动端响应式

**P2（储备，7项）**：用户系统、翻译历史、多翻译引擎、本地离线翻译、超分辨率、API开放、更多语言

### 3.2 明确不做（本期）
漫画上色、CLI/WebSocket模式、MTPE人工后编辑、PDF/PSD/XCF导出、浏览器插件、视频翻译

### 3.3 里程碑交付物
- M1：技术验证Demo（流水线跑通）
- M2：MVP完整Web应用（P0全部功能）
- M3：测试通过稳定版本
- M4：线上正式发布

## 四、技术方案

### 4.1 总体架构
```
[Web前端：上传/语言选择/进度条/预览/下载]
              │ REST API
[Python FastAPI 后端]
  ├── 任务管理（异步任务 + 进度状态）
  ├── 翻译流水线：文本检测 → OCR → 翻译 → 图像修复 → 渲染
  ├── 专有名词词典服务（SQLite/JSON）
  └── 文件存储（临时目录，完成后清理）
[Docker Compose 一键部署（预装模型）]
```

### 4.2 技术选型
| 模块 | 方案 | 说明 |
|------|------|------|
| 前端 | 轻量Web单页（HTML+JS+fetch）+ ui-ux-pro-max 设计规范 | 中文界面，简洁引导式交互，单人可维护 |
| 后端 | Python + FastAPI | 异步高并发，生态成熟 |
| 文本检测 | ctd / dbconvnext | 气泡框定位 |
| OCR | manga-ocr / 48px 漫画OCR | 专为漫画优化 |
| 翻译 | sakura / 在线大模型API（日→中）；DeepL / 在线大模型API（英→中） | 可插拔适配器 |
| 图像修复 | lama_large | 文字擦除 |
| 渲染 | 自动排版引擎 | 保持原位置尺寸，中文渲染 |
| 部署 | Docker Compose + 云服务器 | 一键启动，HTTPS |

### 4.3 关键接口
- `POST /api/translate`：上传图片+语言参数 → 任务ID
- `GET /api/translate/{id}/status`：进度查询
- `GET /api/translate/{id}/result`：结果图获取
- `GET/POST/DELETE /api/glossary`：专有名词词典管理

## 五、项目计划

### 5.1 时间表（9天冲刺版，总计≤9天）

| 阶段 | 周期 | 主要任务 | 里程碑 |
|------|------|----------|--------|
| 阶段1 准备 | Day 1 | 环境搭建、OCR/翻译/修复模型验证、项目骨架 | M1 流水线Demo跑通 |
| 阶段2 核心开发 | Day 2-6 | 后端流水线+API → 轻量前端界面 → 专有名词、错误处理（后端优先串行） | M2 MVP联调完成 |

> - **必保核心**：上传、语言选择、翻译流水线（保持排版）、预览、下载、进度条、错误提示
> - **尽力完成**：专有名词管理（可先做简化JSON录入）、内置精简词库
> - **必须裁剪**：前端重型框架/复杂动效，前端以功能可用为先；测试聚焦端到端主流程
> - **可推迟P1**：批量上传、ZIP导出、自动检测源语言等一律推迟到9天后迭代

### 5.2 关键里程碑
| 里程碑 | 时间 | 验收物 |

| M1 | Day 1 | 翻译流水线Demo（检测→OCR→翻译→修复→渲染） |

## 六、资源需求

### 6.1 人力资源
| 角色 | 人数 | 职责 |
|------|------|------|
| 全栈开发（本人）+ AI辅助 | 1 | 后端流水线、API、前端界面、测试、部署、文档 |

> **开发方式：Vibe Coding（AI辅助编码）**
> - 由AI生成大部分代码（后端流水线、API、前端界面），本人负责架构决策、需求把关、集成与实测验证
> - 采用「后端流水线优先 → 精简前端 → 集成部署」串行路径
> - 前端用轻量单页（HTML+JS+fetch）而非重型框架，最大程度复用竞品开源组件
> - AI生成代码必须逐一人工审查并端到端实测，范围按「必保/尽力/裁剪」严格分层

### 6.2 硬件与云资源
- **开发期**：使用本人笔记本（RTX 5060 Laptop，8GB显存）即可，本地负载约2-3GB显存，单张翻译预计10-30秒
- **生产期（MVP）**：单用户场景可直接复用本地笔记本运行（本地Docker）；如需对外提供多人访问，再按需购买云GPU实例（支持CPU降级模式）
- 域名 + HTTPS证书（对外发布时）

> **结论**：RTX 5060 8GB 足以支撑开发与单用户MVP运行，无需为开发期购置GPU云服务器。翻译引擎保持在线API（本地大模型会因8GB显存不足与OCR/修复模型争抢显存，禁用）。

### 6.3 外部依赖
- 在线翻译API（DeepL / 大模型API）：需申请密钥，评估配额与成本
- 开源模型下载：manga-ocr、lama_large、检测模型（免费）

## 七、风险评估

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|----------|
| OCR对艺术字/小字识别率不稳 | 高 | 中 | 漫画专用模型 + 超分预处理（P1） |
| 在线翻译API限流/成本 | 中 | 中 | 多引擎可插拔（P2）、译文缓存、错误重试 |
| 模型体积大致部署慢 | 中 | 高 | Docker预装模型、首次启动预加载 |
| GPU资源稀缺 | 中 | 中 | CPU/GPU双模式自动降级 |
| **进度风险（单人9天）** | **高** | **高** | MVP范围分层（必保/尽力/裁剪）、后端优先串行、前端轻量化单页、复用竞品开源组件、砍P1功能 |
| **AI代码质量风险（vibecoding）** | 中 | 中 | AI生成代码逐一人工审查、以端到端实测为准、控制单次AI产出规模避免失控 |
| 开源模型许可限制 | 低 | 低 | 立项时核对模型License（避免GPL传染） |

## 十、结论与建议

本项目定位清晰、差异化明确，技术方案有成熟开源参考（manga-image-translator）可大幅降低研发风险。**单人9天冲刺版（Vibe Coding）**即可上线MVP核心功能，建议**批准立项**：优先保障Day 1技术验证（模型效果与License确认），采用「AI辅助生成 + 人工审查实测」的vibecoding开发路径，按「必保/尽力/裁剪」分层严格控制范围。
