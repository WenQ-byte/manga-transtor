# 阶段升级路线图

本文档用于交接后续 Codex：说明当前项目下一阶段应该做什么、为什么做、哪些事情暂时不要发散。

## 当前判断

项目已经具备漫画翻译的核心流水线：上传图片、检测文字、OCR、擦除、气泡分组、翻译、渲染、预览和下载。老师反馈“项目比较单薄”时，不建议只靠继续微调某一条翻译路径来回应；更有价值的是补上用户可感知的完整使用体验，让项目看起来像一个可以长期使用的产品。

当前最值得优先做的是“翻译任务工作台”：每次翻译任务做成接近 ChatGPT 的对话/任务流界面，先只支持图片输入。用户在底部上传或粘贴图片，系统在对话流中逐张输出进度、完成预览、重新翻译和下载入口。每张图片完成后立刻可预览，不需要等整批任务全部结束。

## 已讨论的升级方向

1. 多语言优化
2. 每张翻译后实时预览，可单张重新翻译、单张下载，也可打包下载
3. 专有名词库扩充与编辑
4. 历史翻译记录
5. 文件夹上传
6. 参考大模型的对话界面
7. 接入 AI 支持自定义翻译风格

## 推荐优先级

### 第一阶段：ChatGPT 式翻译任务界面

目标是先做出可演示的体验闭环，不要求一开始支持所有输入类型。

- 只支持图片输入，不做文本、PDF、网页等输入。
- 底部保留输入区，用于上传或粘贴图片并提交翻译任务。
- 主区域采用对话/任务流形式展示，不再只是传统表单加结果页。
- 每张图片完成后立即显示预览。
- 每张图片支持单独重新翻译。
- 每张图片支持单独下载。
- 批量任务仍支持统一打包下载 ZIP。
- 任务状态要能体现：等待中、处理中、完成、失败。
- 失败的单张图片不应阻塞其他已完成图片的预览和下载。

这个阶段价值最高，因为它能直接改善演示观感，也能自然承接后面的历史记录、文件夹上传和自定义风格。

### 第二阶段：侧边栏与专有名词库入口

侧边栏结构按以下方式理解：

- “翻译任务：……”是一个任务入口，前面带侧边栏图标。
- “翻译任务”和“专有名词库”同级。
- 点击“专有名词库”后，主区域切换为词库编辑界面。
- 词库不要作为翻译任务表单的一个附属弹窗长期堆叠在页面里。

词库编辑界面应优先支持基础 CRUD、搜索、按语言方向筛选。词库本身用于提升翻译质量，但它的界面价值也很明显，适合作为作品完整度的一部分。

### 第三阶段：性能优化

当前主要性能瓶颈在 OCR，尤其 PaddleOCR 会对每个文字区域执行完整 `predict()`。英文/中文路径主要依赖 PaddleOCR，因此会更容易感知到慢。

优先方案：

- PaddleOCR 默认优先使用 GPU，例如 `MANGA_PADDLE_DEVICE=gpu:0`。
- 支持指定 `gpu:1` 等设备，也支持 `cpu` 强制使用 CPU。
- GPU 不可用、CUDA/PaddlePaddle GPU 版本不匹配、显存不足或模型初始化失败时自动回退 CPU。
- 日志或任务元数据中记录请求设备、实际设备和回退原因。
- 不要在每张图片或每个文字区域重复初始化 PaddleOCR；不同语言实例继续缓存复用。
- 不要承诺固定加速倍数，实际提升取决于显卡、显存、CUDA/cuDNN、PaddlePaddle 版本、图片大小、文字区域数量和低置信度回退次数。

GPU 也可以参与其他环节：

- MIT48 / manga-ocr：日语路径使用深度模型时有价值。
- LaMa 修复：启用神经网络修复时 GPU 有价值。
- 翻译接口、文字渲染、文件打包：主要瓶颈不是 GPU，优先级低。

注意：不要通过并发整条流水线来加速。当前模型和引擎有共享状态，批量推理必须保持串行，保留单 worker 和 `_pipeline_lock`。

### 第四阶段：翻译质量继续细化

系统已经具备中、日、英六条翻译路径的基础框架，但不要平均用力。当前用户已重点优化日→中，并准备继续优化英→中。

建议顺序：

- 先保证日→中、英→中两条主路径稳定。
- 中→日、中→英、日→英、英→日先保持可用，不急于深度润色。
- 专有名词库应优先服务日→中、英→中。
- 自定义翻译风格应在任务界面稳定后再接入，作为任务级设置或侧边栏设置。

## 暂缓事项

以下方向有价值，但不建议压在第一阶段里一起做：

- 完整账号体系
- 团队协作
- 全量历史任务持久化和复杂检索
- 文件夹上传的复杂递归规则
- 所有六条翻译路径的深度质量打磨
- 多任务并发模型推理

## 给后续 Codex 的实现提醒

- 先读 `AGENTS.md`，再读本文档。
- 如果用户要求“第一阶段”，默认指 ChatGPT 式翻译任务界面。
- 如果用户要求“GPU 加速”，优先处理 PaddleOCR 设备配置和安全回退。
- 如果用户要求“文件夹上传”，先确认是在现有批量上传基础上增加前端文件夹选择，还是要做历史任务/目录结构保留。
- 所有 UI 文案使用中文。
- 前端继续使用 React/Vite、Tailwind、Framer Motion、GSAP、Lucide 的现有风格。
- 后端测试使用 `.\.venv\Scripts\python.exe backend\tests\test_app.py`，不是 pytest。
- 前端构建在 Windows 上使用 `cd frontend; npm.cmd run build`。
