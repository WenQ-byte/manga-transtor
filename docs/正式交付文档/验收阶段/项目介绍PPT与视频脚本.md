# 项目介绍 PPT 与产品视频脚本

## 一、答辩 PPT（15 页，建议 8—10 分钟）

本 PPT 以当前代码、测试和真实交互记录为事实来源。完整的 Kimi 生成提示词、逐页版式约束、图片占位规则和演讲备注见同目录的《Kimi_PPT生成提示词与逐页内容规范.md》；成品位于 `ppt/AI_Manga_Translator_验收汇报.pptx`。

### 第 01 页：封面——项目定位

展示项目全名、ComicX、初步验收汇报和学生信息。定位为“面向漫画图片的 OCR、翻译、擦除修复与中文排版一体化工具”。预留项目主界面或原图/译图对照图。

### 第 02 页：为什么要做——问题与价值

说明竖排、弯曲、密集文字和复杂背景带来的识别难点；普通 OCR 不负责原文擦除、背景修复和译文排版；逐句翻译容易丢失气泡上下文和术语一致性。对比人工处理链与项目自动任务链。

### 第 03 页：做什么——需求范围与实现边界

分栏展示当前已实现、依赖环境和后续规划。已实现包括图片/文件夹输入、日英重点翻译、任务进度、逐图预览、下载、重试、术语库、文本框编辑、手动擦除和撤销。历史记录、章节管理、EPUB/CBZ/PDF、团队协作和云端 GPU 归入规划。

### 第 04 页：用户怎么用——完整任务流

上传/粘贴图片或文件夹 → 选择源语言、目标语言和润色设置 → 提交 → 查看逐图进度 → 完成即预览 → 编辑或重新翻译 → 单张下载或批量 ZIP 下载。每一步都说明可观察结果。

### 第 05 页：系统怎么组成——总体架构

展示 React/Vite 前端、FastAPI API、TranslationTaskManager、Pipeline、SQLite/本地文件存储五层结构，并解释单 worker 和流水线锁。明确“批量是任务编排，模型推理保持串行”。

### 第 06 页：核心流程——一张图片如何变成译图

严格展示 `detect → ocr → inpaint → bubble grouping → translate → quality assessment → render`。重点解释先在修复后的干净图上分组，再用原图轮廓否决跨气泡合并；翻译以气泡整块为单位，最后按掩膜和气泡几何约束排版。

### 第 07 页：识别难点——OCR、方向和引擎回退

展示文字框/多边形、识别文本、置信度和横竖排方向等中间信息。MIT/CTD 和 MIT48 作为主要路线，manga-ocr 只补救 MIT48 完全未读出的空行，PaddleOCR/CV 作为可配置回退，不宣称并行运行。

### 第 08 页：图像重建——擦除、修复和气泡分组

说明文字多边形、Otsu 笔画候选、检测掩膜和注音扩展如何合并；默认 OpenCV 局部修复，LaMa 作为可选增强；刊头、拟声词等非气泡文字保留。展示可靠气泡掩膜、安全扩展框、紧致文本框、跳过气泡的分级回退。

### 第 09 页：翻译怎么更稳——上下文、术语和质量检查

说明气泡整块翻译、原文换行和句序保持、术语库整词替换、多后端回退。展示质量告警：回退后端、译文过短、日文残留、数字/单位/符号遗漏、术语遗漏和模型解释文字。AI 润色复用已有 DeepSeek，失败保留原译文。

### 第 10 页：译文如何落回画面——排版与人工编辑

说明横排均衡断行、竖排按气泡分列、字号和字距控制、气泡掩膜裁剪及几何回退。展示文本框移动、尺寸调整、字体/字号/颜色/方向预览、文本框新增/删除、局部擦除和撤销。

### 第 11 页：任务与批量——可用性和安全边界

展示批量校验 → 创建子任务 → 逐张串行处理 → 汇总平均进度 → 生成 ZIP。说明原文件名和顺序、重名改名、`manifest.json`、`errors.txt`、部分成功和单张重试；同时说明文件类型、大小、数量和结果路径校验。

### 第 12 页：产品界面——从工具到任务工作台

展示“翻译任务”和“专有名词库”同级的侧边栏、对话式任务流、底部上传/粘贴入口、逐图状态和结果卡片。说明界面设计围绕“任务进行到哪、哪张失败、下一步做什么”。

### 第 13 页：AI 协作——人工决策与迭代证据

明确人工负责需求约束、事实核查、运行验证、体验判断和最终取舍；AI 辅助代码阅读、问题定位、方案草拟、局部实现和测试建议。展示词库删除、AI 润色约束、擦除撤销、字体预览、文本框编辑和文件夹上传等真实协作证据。

### 第 14 页：怎么证明——测试与现场演示

展示截至 2026-09-03 的后端 171 项 unittest 通过、前端 Vite 生产构建成功。现场顺序：选择日文/英文样例 → 上传/粘贴 → 查看进度 → 展示译图 → 打开编辑 → 修改一处 → 下载。主动声明没有统一数据集下的 OCR 准确率、翻译准确率和平均耗时统计。

### 第 15 页：结论、边界与答辩入口

总结“图片输入—识别—修复—翻译—排版—编辑—下载”闭环，说明核心难点和下一步方向。左栏列当前可验收能力，右栏列历史记录、章节管理、更多格式、团队协作和云端 GPU 等扩展方向，最后进入 Q&A。

## 二、产品视频脚本（约 3—4 分钟）

### 片段 1：项目介绍（20 秒）

旁白：这是 ComicX 漫画多语言智能翻译系统。它面向漫画图片，将文字检测、OCR、背景修复、上下文翻译和中文排版整合到一个本地 Web 应用中，重点支持日语或英语到中文的译图生成。

### 片段 2：上传任务（30 秒）

操作：选择一张图片，或通过文件夹选择/拖入方式导入多张图片；选择源语言和目标语言；按需打开 AI 润色并选择风格；提交任务。

### 片段 3：处理过程（50 秒）

旁白：系统依次完成文字检测、OCR 识别、原文擦除、背景修复、气泡分组、整块翻译、质量检查和中文排版。批量任务逐张显示状态，单张完成后立即可以预览。

### 片段 4：结果编辑（60 秒）

操作：打开大图预览，选择一个文字区域，修改译文；拖拽文本框或调整边缘；切换字体、字号、颜色和方向并查看预览；使用画笔进行局部擦除，再点击撤销。

### 片段 5：术语库和下载（30 秒）

操作：打开“专有名词库”，新增、搜索或删除一个角色名词条；回到翻译任务查看术语应用；点击单张下载，或对批量结果下载 ZIP。

### 片段 6：总结（20 秒）

旁白：项目的核心不是单独调用翻译接口，而是把漫画检测、识别、擦除修复、气泡上下文、质量检查和排版渲染组成一条可观察、可编辑、可回退的工程化流水线。
