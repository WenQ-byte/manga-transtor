## 1 项目提出

### 1.1 项目名称

漫画多语言智能翻译系统（ComicX）。

### 1.2 项目简介

本项目面向日语、英语和中文漫画图片，提供基于 Web 的文字检测、OCR 识别、原文擦除、背景修复、气泡分组、上下文翻译和中文排版能力。用户上传图片后，可以在网页中查看处理进度、预览结果并下载译图；多张图片可以批量处理并统一打包。

### 1.3 项目目标

1. 降低漫画翻译和排版的操作门槛。
2. 重点支持日语→中文、英语→中文，并保留中文、日语、英语三语互译框架。
3. 尽可能保留漫画原有气泡、分镜、阅读顺序和视觉结构。
4. 支持单图、批量和文件夹导入，提供逐图状态、重试、下载和 ZIP 导出。
5. 通过专有名词库和 AI 润色功能提高译文一致性和可读性。

### 1.4 系统边界

系统输入为 JPG、JPEG、PNG、WebP、BMP 等漫画图片；输出为重新排版后的 PNG 译图。系统不包含账号体系、云同步、团队协作、PDF/PSD 出版格式处理和从零训练模型。翻译质量受 OCR、图片质量、外部翻译服务和漫画艺术字影响。

## 4 风险评估和规避

### 4.1 技术风险

1. OCR 对艺术字、低清图片和复杂竖排文字识别不稳定。
2. 背景修复和气泡边界判断可能影响人物线稿或相邻气泡。
3. 外部翻译 API 可能失败、限流或产生质量波动。
4. 多模型共享状态不适合并发推理。

**解决措施：**采用 MIT/Paddle 多路线回退；使用原图边界否决和多级渲染回退；记录实际翻译后端和质量警告；批量任务采用单 Worker 与流水线锁串行推理。

### 4.2 管理风险

1. VibeCoding 容易出现只接受 AI 结果、不理解代码的问题。
2. 功能扩展可能超出验收范围，导致核心闭环不稳定。

**解决措施：**每轮交互先明确目标和约束，要求 AI 先读代码；学生对关键方案进行反问、验证和本地测试；优先保证“上传—处理—预览—下载”闭环。

### 4.3 其他风险

1. 项目文档可能把计划功能误写成已实现功能。
2. 第三方模型和代码可能带有独立许可证要求。

**解决措施：**交付文档以当前代码、测试和截图为事实来源；对已实现、部分实现和后续计划分栏说明；在 `THIRD_PARTY.md` 中记录第三方许可信息。
