# 数据库设计说明

## 一、数据库选型

系统使用 SQLite，适合本地部署和 MVP 阶段。图片文件本体保存在本地文件系统，数据库只保存路径、状态和元数据，避免把大文件直接写入数据库。

## 二、任务表 `tasks`

| 字段 | 含义 |
|---|---|
| `id` | 任务唯一标识 |
| `source_lang` | 请求的源语言 |
| `target_lang` | 目标语言 |
| `status` | queued、processing、completed 或 failed |
| `progress` | 0～100 的任务进度 |
| `step` | 当前流水线步骤 |
| `error` | 失败原因 |
| `result_path` | 翻译结果相对路径 |
| `original_path` | 原图路径 |
| `text_count` | 识别到的文字区域数量 |
| `duration_ms` | 处理耗时 |
| `meta` | JSON 格式的批次、语言检测、后端和质量信息 |
| `created_at` / `updated_at` | 创建和更新时间 |

## 三、术语表 `glossary`

| 字段 | 含义 |
|---|---|
| `id` | 词条编号 |
| `source` | 原词 |
| `target` | 目标译词 |
| `lang` | 源语言 |
| `target_lang` | 目标语言 |
| `note` | 词条备注 |
| `created_at` / `updated_at` | 创建和更新时间 |

系统对 `source、target、lang、target_lang` 建立唯一约束，避免重复词条。

## 四、数据流

上传图片后先保存到上传目录，再创建任务记录。任务完成后，结果图片保存到结果目录，数据库更新结果路径、状态和处理元数据。下载接口只允许解析服务端记录中的安全相对路径，并对 ZIP 文件名进行清理。
