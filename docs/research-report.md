## 一、调研概述

### 1.1 调研目的
1. 验证「漫画多语言智能翻译系统」的市场需求与用户痛点
2. 深入分析核心竞品 manga-image-translator 的功能、页面风格与易用性，识别差异化机会
3. 形成完整的产品功能矩阵，明确需求优先级（P0/P1/P2），支撑立项决策与9天开发计划

### 1.2 调研范围与方法
| 维度 | 内容 |
|------|------|
| 需求调研 | 原始需求分析、用户痛点、用户画像与核心要素 |
| 竞品分析 | manga-image-translator（GitHub 10.3k Star）源码与文档研究 |
| 功能矩阵 | 竞品功能 vs 本产品功能逐项对比，按 P0/P1/P2 定级 |

### 1.3 核心结论速览
- 市场存在真实需求：**优质国外漫画因语言壁垒无法被普通读者与中小出版社消化**
- 竞品技术成熟但**易用性差、门槛高**，存在明确的差异化空间
- 本产品定位：**零配置、一键式、保持原排版的Web翻译平台**，主打图形化专有名词管理与友好UI
- MVP聚焦**日语→中文、英语→中文**两个语言组合，P0共10项核心功能

## 二、需求调研

### 2.1 市场背景与需求来源
- 全球漫画市场持续增长，日漫、英漫等优质内容在国内及海外均有大量读者
- 语言障碍是读者理解内容的最大阻碍：**看不懂 → 放弃阅读 → 内容价值无法释放**
- 人工翻译成本高、周期长，中小出版社难以负担专业翻译团队
- 现有通用翻译器对漫画排版、气泡文字适配差，无法保持原图排版

### 2.2 用户痛点分析

| 痛点 | 场景 | 影响 |
|------|------|------|
| 语言壁垒 | 读者看到优秀国外漫画但读不懂 | 阅读体验中断，内容传播受阻 |
| 人工翻译贵且慢 | 出版社引进漫画需逐话翻译 | 周期长、成本高、错失时效 |
| 通用翻译不适配 | 用通用翻译器逐字翻译，破坏排版 | 阅读体验差，无法直接使用 |
| 专有名词不一致 | 角色名/招式名翻译前后不一 | 影响理解与品牌统一 |

### 2.3 用户画像及核心要素

#### 画像A：漫画爱好者
| 核心要素 | 描述 |
|----------|------|
| 基本信息 | 18-35岁，互联网原住民，日漫/英漫深度读者 |
| 使用场景 | 在线阅读遇到语言障碍时，需要即时翻译单张/多张漫画图 |
| 核心诉求 | 快速看懂内容、翻译后保持原图可读性、操作简单零门槛 |
| 决策因素 | 免费或低成本、速度快、效果好 |
| 使用频次 | 高频（每次阅读多个片段） |
| 付费意愿 | 低-中，偏向免费增值模式 |

#### 画像B：引进国外漫画的出版社
| 核心要素 | 描述 |
|----------|------|
| 基本信息 | 出版企业，编辑/版权/翻译团队 |
| 使用场景 | 审阅海外样张、评估引进价值、辅助初译、术语统一 |
| 核心诉求 | 批量处理、保持排版、专有名词/术语一致、可复现 |
| 决策因素 | 质量稳定、效率、术语管理能力 |
| 使用频次 | 中-高（按项目批量使用） |
| 付费意愿 | 中-高，可接受企业付费 |

### 2.4 需求整理
- **核心功能**：上传漫画图片 → 翻译气泡框文字 → 保持原排版 → 预览下载
- **差异化功能**：图形化专有名词录入（自定义词典 + 内置词库）
- **首发语言**：日语→中文、英语→中文
- **形态**：Web应用，上传即用，无需安装配置

## 三、竞品分析：manga-image-translator

### 3.1 基本信息
| 项目 | 信息 |
|------|------|
| 项目名称 | Manga/Image Translator |
| 开源地址 | https://github.com/zyddnys/manga-image-translator |
| Star / Fork | 10.3k / 1.1k |
| 许可证 | GPL-3.0 |
| 技术栈 | Python 3.10+ + FastAPI + TypeScript前端 |
| 部署方式 | Docker（约15GB镜像）、pip/venv、CLI |
| 在线Demo | https://touhou.ai/imgtrans/ |

### 3.2 技术架构
**翻译流水线**：文本检测 → OCR → 翻译 → 图像修复 → 渲染

| 模块 | 可选方案 | 推荐/默认 |
|------|----------|-----------|
| 文本检测 | default / dbconvnext / ctd / craft / paddle | default（ctd提升检测量） |
| OCR | 32px / 48px / 48px_ctc / mocr | 48px（日语） |
| 翻译 | sugoi / sakura / deepl / chatgpt / deepseek / nllb 等20+种 | 日→英：sugoi；日→中：sakura/openai |
| 图像修复 | lama_large / lama_mpe / sd | lama_large |
| 渲染 | default / manga2eng / none | default（manga2eng贴合气泡更佳） |
| 辅助 | 超分辨率（esrgan/waifu2x）、上色（mc2） | 按需 |

### 3.3 功能分析
- 多形态：CLI、Web、API、WebSocket 四种运行模式
- 多格式输出：png/webp/jpg/jpeg/xcf/psd/pdf
- 词典支持：预译词典、后译词典、Glossary、sakura_dict（专有名词）
- 专业编辑：MTPE人工后编辑、手动排版准备
- 容错机制：重试、跳过错误、模型TTL

### 3.4 页面风格与易用性评价
| 维度 | 评价 |
|------|------|
| 视觉设计 | 简洁偏工程风格，功能性为主，装饰少 |
| 信息架构 | 功能入口清晰，但参数配置项极多，新手上手门槛高 |
| 交互反馈 | 有进度反馈，但实时性一般 |
| 易用性 | **中等偏低**：30+命令行参数 + JSON配置，普通用户难调优 |
| 移动端 | 较弱，主要面向桌面端 |

**优点**：翻译效果好（日语优化明显）、语言支持多（含20种次要语言）、部署形态丰富、社区活跃。
**缺点**：部署复杂（15GB镜像）、配置门槛高、无用户系统、批量交互弱、专有名词需编辑本地文件、在线Demo不稳定。

### 3.5 差异化机会（本产品切入点）
| 竞品短板 | 本产品机会 |
|----------|-----------|
| 配置复杂、门槛高 | 简化为「上传→选语言→翻译」三步，零配置 |
| 无友好Web界面 | 精心设计的中文UI，引导式操作 |
| 专有名词需编辑文件 | 图形化专有名词录入界面 |
| 部署复杂 | 一键启动（Docker Compose），面向普通用户 |
| 无进度反馈 | 分步进度条（检测→识别→翻译→渲染） |

### 3.6 可借鉴技术选型
| 模块 | 建议 | 理由 |
|------|------|------|
| OCR | manga-ocr / 48px 模型 | 专为漫画优化 |
| 文本检测 | ctd / dbconvnext | 气泡框定位效果好 |
| 翻译（日→中） | sakura / 在线大模型API | 质量与成本平衡 |
| 翻译（英→中） | DeepL / 大模型API | 英语质量高 |
| 图像修复 | lama_large | 社区验证最佳方案 |
| 渲染 | 基于检测区域自动排版 | 保持原排版 |

## 四、功能矩阵

### 4.1 需求级别定义
| 级别 | 定义 | 策略 |
|------|------|------|
| **P0** | 核心功能，MVP必须实现 | 无此功能产品不可用 |
| **P1** | 重要功能，发布后尽快迭代 | 显著提升产品价值 |
| **P2** | 增强功能，视资源安排 | 锦上添花，差异化储备 |

### 4.2 竞品 vs 本产品功能对比（核心摘录）
| 功能 | 竞品 | 本产品 | 级别 | 说明 |
|------|:---:|:---:|:---:|------|
| 文本检测（气泡框定位） | ✅ | ✅ | **P0** | 检测文字区域 |
| OCR文字识别 | ✅ | ✅ | **P0** | 识别气泡内文字 |
| 机器翻译 | ✅ | ✅ | **P0** | 日→中、英→中 |
| 图像修复 + 渲染排版 | ✅ | ✅ | **P0** | 清除原文并保持原排版 |
| 网页上传/预览/下载 | ✅ | ✅ | **P0** | 核心交互闭环 |
| 翻译进度条反馈 | ⚠️ | ✅ | **P0** | 分步显示 |
| 图形化专有名词录入 | ❌ | ✅ | **P0** | **核心差异化** |
| 批量上传 / ZIP导出 | ✅ | ❌（P1） | **P1** | 多张批量处理 |
| 自动检测源语言 | ✅ | ❌（P1） | **P1** | 免手动选择 |
| 用户系统 / 翻译历史 | ❌ | ❌（P2） | **P2** | 后续迭代 |
| 多翻译引擎 / 离线翻译 | ✅ | ❌（P2） | **P2** | 增强能力 |
| 漫画上色 | ✅ | ❌ | 不做 | 超出范围 |

### 4.3 本产品功能清单与优先级（汇总）

**P0（MVP核心，共10项）**
| 编号 | 功能 | 说明 |
|------|------|------|
| P0-01 | 图片上传 | 单张，JPG/PNG/WebP，建议≤10MB |
| P0-02 | 语言选择 | 下拉框：日→中、英→中 |
| P0-03 | 文本检测 | 气泡框/文字区域定位 |
| P0-04 | OCR识别 | 气泡内文字识别 |
| P0-05 | 机器翻译 | 保持原排版，翻译气泡文字 |
| P0-06 | 图像修复+渲染 | 擦除原文并渲染译文 |
| P0-07 | 进度条反馈 | 分步显示 |
| P0-08 | 网页预览 | 结果即时预览 |
| P0-09 | 下载单张 | 下载翻译后图片 |
| P0-10 | 专有名词管理 | 图形化录入 + 内置词库 |

**P1（重要迭代，共6项）**：批量上传、ZIP打包导出、自动检测源语言、词典导入/导出、竖排文字支持、移动端响应式

**P2（增强功能，共7项）**：用户系统、翻译历史、多翻译引擎、本地离线翻译、超分辨率、API开放、更多语言

### 4.4 明确不做的功能
漫画上色、CLI/WebSocket模式、MTPE人工后编辑、PDF/PSD/XCF导出、浏览器插件（「网站翻译」定义为网页在线翻译，非插件）、视频字幕翻译

## 五、结论与建议

### 5.1 调研结论
1. **需求真实**：漫画翻译存在明确痛点与两类可触达用户，市场缺口在于「易用的漫画翻译工具」
2. **竞品可参考不可照搬**：manga-image-translator 技术方案成熟（可直接借鉴流水线选型），但其易用性短板正是本产品机会
3. **定位清晰**：零配置、保持排版、图形化专有名词管理，差异化明确
4. **MVP收敛**：首发日→中、英→中两个语言组合，P0十项核心功能即可形成可用产品

### 5.2 建议
1. **技术**：直接复用竞品验证过的模型选型（manga-ocr + ctd + lama_large），翻译引擎用在线API，降低研发风险
2. **产品**：MVP围绕「三步操作」构建体验，重点打磨专有名词录入与进度反馈两个差异化点
3. **开发**：单人9天 Vibe Coding 冲刺，按「必保核心（7项）→ 尽力（专有名词/词库）→ 裁剪（动效/完整测试）」分层推进
4. **后续**：P1优先做批量与ZIP导出（出版社刚需），P2再引入用户系统与历史记录
